# Resume

`resume.html` — источник. `Alexandra_Miron_Resume.pdf` — собранный файл.

## Как пересобрать PDF

Открыть `resume.html` в браузере → печать → «Сохранить как PDF», поля 10 мм / 12 мм, A4,
фоновая графика включена. Либо через headless Chromium — см. историю коммитов.

## Почему именно так свёрстано

Прошлая версия резюме была набрана шрифтом **Calibri**, у которого есть OpenType-лигатура
для пары `ti`. При экспорте лигатурные глифы попали в PDF без таблицы соответствия Unicode,
и любой парсер читал `Op miza on` вместо `Optimization`, `Tes ng` вместо `Testing`,
`acquisi on` вместо `acquisition`. Визуально файл был безупречен — для ATS он был пустым
на всех дорогих ключевых словах.

Поэтому здесь:

- **Liberation Sans** (метрический аналог Arial) — нет лигатуры `ti`
- `font-variant-ligatures: none` и `font-feature-settings: "liga" 0` — лигатуры выключены явно
- **`letter-spacing: 0` в заголовках секций.** Разрядка заставляет Chromium вставлять пробелы
  внутрь слов при извлечении: `TOOLS` превращался в `TO O L S`, и парсер переставал узнавать
  секцию
- **`white-space: nowrap` на ссылках** — иначе перенос внутри URL съедал дефис, и
  `portfolio-alexmir8` извлекался как `portfolioalexmir8`
- **Нативные маркеры списка** вместо `::before` — псевдоэлементы попадают в извлечённый текст
  отдельными строками
- Одна колонка, без таблиц и текстовых блоков — так парсер не путает порядок чтения

## Проверка перед каждой отправкой

```sh
pdftotext Alexandra_Miron_Resume.pdf - | grep -i optimization
```

Или без терминала: открыть PDF и нажать Ctrl+F по словам `optimization`, `testing`,
`qualification`, `portfolio`. Не нашлось — ATS тоже не найдёт.
